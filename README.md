# Практическая работа №3 — Процессы

**Дисциплина:** Операционные системы
**Вариант:** B
**Язык:** Python 3

## 🎯 Цель

Изучение создания и управления процессами с использованием `fork()`, `exec()`, `wait()`, а также исследование Zombie, Orphan и Copy-on-Write.

## 1. Дерево процессов

```bash
python3 ptree.py
```

Выводит PID, состояние и RSS процессов текущего пользователя в виде дерева.

> Работа выполнялась на macOS, где отсутствует `/proc`, поэтому для получения информации о процессах используется `ps`.

## 2. `fork()` + `exec()`

```bash
python3 runner.py 3 sleep 2
```

Программа создаёт 3 дочерних процесса, запускает команду через `exec()` и ожидает их завершения.

Пример:

```text
PID=40605 | Код возврата=0 | Время работы=2.015 сек
PID=40604 | Код возврата=0 | Время работы=2.016 сек
PID=40603 | Код возврата=0 | Время работы=2.016 сек
```

## 3. Zombie и Orphan

### Zombie

```bash
python3 zombie.py
```

Проверка:

```bash
ps -axo pid,ppid,state,command | grep zombie
```

Zombie — завершившийся процесс, информация о котором ещё не была получена родителем через `wait()`.

### Orphan

```bash
python3 orphan.py
```

Проверка:

```bash
ps -axo pid,ppid,state,command | grep orphan
```

Orphan — дочерний процесс, родитель которого завершился раньше него. Операционная система перепривязывает такой процесс к другому системному родителю.

---

## 4. Copy-on-Write

```bash
python3 cow_memory.py
```

В программе создаётся список из **10 000 000 элементов**, после чего выполняется `fork()`.

Результат эксперимента:

```text
RSS до изменения списка: 7424 KB
RSS после изменения списка: 85792 KB
Изменение RSS: 78368 KB
```

После изменения данных дочерним процессом увеличивается его RSS, что демонстрирует механизм **Copy-on-Write** — копирование страниц памяти происходит при записи.

---

## 🧠 Контрольные вопросы

**Что возвращает `fork()`?**
В родителе — PID дочернего процесса, в ребёнке — `0`.

**Что будет при `exec()` без `fork()`?**
Текущая программа будет заменена новой, без создания отдельного процесса.

**Zombie vs Orphan:**
Zombie уже завершился, но ещё не был обработан родителем. Orphan продолжает работать после завершения родителя.
